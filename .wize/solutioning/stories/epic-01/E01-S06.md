# Story: Persistência de Sessão e Refresh Automático

## Context
App lembra que o usuário está logado. Access token expira? Refresh automático sem o usuário perceber.

## Sources of truth
- `architecture.md` (Process Patterns — Authentication Flow)

## Acceptance criteria
- [ ] MMKV armazena access_token + refresh_token (encrypted)
- [ ] App verifica token ao abrir — se válido, pula login
- [ ] Access token expirado → chama `POST /auth/refresh` automaticamente
- [ ] Refresh token expirado → redireciona para login
- [ ] Axios interceptor: 401 → tenta refresh → retry request original
- [ ] Logout limpa MMKV e chama `POST /auth/logout`

## Restrictions
- **Out of scope:** biometria, PIN code
- **Protected:** nenhum
- **Compatibility:** MMKV funciona em Android
- **Security:** tokens nunca em plain text; logout limpa tudo

## Notes for Shuri (Dev)
- Interceptor em `services/api.ts`
- Retry automático com backoff se refresh falhar
- Toast "Sessão expirada" se refresh falhar

## Validation contract
- **Testes:**
  - Unit: MMKV read/write
  - Integration: interceptador com token expirado → refresh → retry
- **NFR:** refresh ≤ 500ms

## Done means
- Usuário abre app 1 dia depois e ainda está logado
- Token expirado é renovado automaticamente
- Testes passam
