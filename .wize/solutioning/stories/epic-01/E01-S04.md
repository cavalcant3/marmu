# Story: Middleware de Autenticação e Proteção de Rotas

## Context
Garantir que apenas usuários autenticados acessem rotas protegidas. Base para todas as APIs de dados.

## Sources of truth
- `architecture.md` (Authentication & Security section)

## Acceptance criteria
- [ ] Middleware `authMiddleware` verifica Bearer token no header `Authorization`
- [ ] Token inválido/expirado → 401 Unauthorized (RFC 7807)
- [ ] Token válido → adiciona `req.user` com id do usuário
- [ ] Rotas protegidas retornam 401 se token ausente
- [ ] Rate limiting: 100 req/min por IP
- [ ] Helmet configurado (headers de segurança)
- [ ] CORS configurado (origem do app mobile)

## Restrictions
- **Out of scope:** RBAC (roles/permissions) — não necessário para MVP single-user
- **Protected:** nenhum
- **Compatibility:** JWT padrão
- **Security:** tokens sempre via HTTPS; nunca em query params

## Notes for Shuri (Dev)
- Middleware em `src/middlewares/authMiddleware.ts`
- Aplicar a todas as rotas exceto `/auth/*` e `/health`
- Helmet + CORS no `app.ts`
- Rate limiter com `express-rate-limit`

## Validation contract
- **Testes:**
  - Unit: authMiddleware com token válido/inválido/ausente
  - Integration: acessar `/orcamentos` sem token → 401; com token → 200
- **NFR:** middleware overhead ≤ 10ms

## Done means
- Rotas protegidas funcionam com/sem token
- Testes passam
