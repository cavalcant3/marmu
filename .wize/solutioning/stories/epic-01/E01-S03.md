# Story: API de Autenticação (Login, Registro, Refresh Token)

## Context
Permitir que o gestor da marmoaria se registre e faça login. JWT protege todas as rotas.

## Sources of truth
- `architecture.md` (Authentication & Security section)
- `prd.md` (LGPD + segurança)

## Acceptance criteria
- [ ] `POST /auth/register` — cria usuário com email, senha, nome, nome_marmoaria
- [ ] `POST /auth/login` — retorna access_token + refresh_token
- [ ] `POST /auth/refresh` — retorna novo access_token usando refresh_token
- [ ] `POST /auth/logout` — invalida refresh_token
- [ ] Senhas hasheadas com bcrypt (cost factor 12)
- [ ] JWT access token expira em 24h, refresh em 7 dias
- [ ] Validação de email único (não permite duplicado)
- [ ] Resposta de erro padronizada (RFC 7807)

## Restrictions
- **Out of scope:** recuperação de senha (post-MVP), OAuth, 2FA
- **Protected:** nenhum
- **Compatibility:** JWT formato padrão
- **Security:** nunca retornar senha_hash nas respostas; validar email no servidor

## Notes for Shuri (Dev)
- Usar `jsonwebtoken` para JWT
- `bcryptjs` para hashing
- Refresh tokens armazenados em tabela `refresh_tokens` (ou cookie httpOnly)
- Zod para validação de inputs

## Validation contract
- **Testes:** 
  - Unit: bcrypt hashing, JWT sign/verify
  - Integration: register → login → access protected route → refresh → logout
- **Checks:** `npm test`, `npm run lint`
- **NFR:** login response ≤ 800ms
