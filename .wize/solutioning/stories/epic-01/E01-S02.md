# Story: Modelagem do Banco de Dados (Prisma Schema)

## Context
Definir todas as tabelas e relacionamentos do Marmu. Base para todas as APIs.

## Sources of truth
- `architecture.md` (Data Architecture section)
- `prd.md` (Scope: orçamentos, pedidos, materiais, usuários)

## Acceptance criteria
- [ ] Tabela `usuarios`: id, email, senha_hash, nome, nome_marmoaria, created_at, updated_at
- [ ] Tabela `materiais`: id, nome, tipo (granito/mármore/porcelanato/outro), preco_por_m2, observacoes, usuario_id, created_at
- [ ] Tabela `orcamentos`: id, cliente_nome, comprimento, largura, area, material_id, preco_sugerido, preco_final, observacoes, status (pendente/aprovado/rejeitado/vencido), validade_dias, created_at
- [ ] Tabela `pedidos`: id, orcamento_id, data_prometida_entrega, data_entrega_real, status (pendente/entregue), observacoes, foto_url, created_at
- [ ] Relacionamentos: usuário → materiais (1:N), orçamento → material (N:1), pedido → orçamento (1:1)
- [ ] Migração inicial gerada e aplicada
- [ ] Seed com materiais de exemplo (para testes)

## Restrictions
- **Out of scope:** índices de performance (otimizar depois), soft delete (pode adicionar depois)
- **Protected:** nenhum
- **Compatibility:** PostgreSQL 14+
- **Security:** senha_hash usa bcrypt (próxima story)

## Notes for Shuri (Dev)
- Usar `@default(uuid())` para IDs
- `@relation` fields para FKs
- `@map` para snake_case no banco
- Gerar seed com 5 materiais de exemplo

## Validation contract
- **Testes:** 1 integration test por tabela (CRUD básico via Prisma)
- **Checks:** `prisma migrate dev`, `prisma db seed`

## Done means
- Schema gerado, migrado e testado
- Seed populado com dados de exemplo
