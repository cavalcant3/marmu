# Story: Tela de Tabela de Preços no App

## Context
Dono cadastra e edita os materiais que trabalha. Tela acessível pelo menu Configurações.

## Sources of truth
- `ux-design/tabela-precos.md`
- `prd.md` (E02)

## Acceptance criteria
- [ ] Lista de materiais agrupados por tipo (Granito, Mármore, etc.)
- [ ] Botão "+ Adicionar Material" abre formulário modal
- [ ] Formulário: nome, tipo (dropdown), preço por m², observações
- [ ] Editar: toca em ícone ✏️, abre modal com dados preenchidos
- [ ] Excluir: toca em 🗑️, confirmação, mantém histórico em orçamentos antigos
- [ ] Busca em tempo real por nome
- [ ] Offline: salva no SQLite local; sync quando online

## Restrictions
- **Out of scope:** importação/exportação de CSV, fotos de materiais
- **Protected:** nenhum
- **Compatibility:** Android
- **Security:** validação de preço > 0

## Notes for Shuri (Dev)
- FlatList com SectionList por tipo
- Zustand store: `materialStore`
- SQLite: tabela `materiais` com `status: 'pending_sync'` para novos registros

## Validation contract
- **Testes:**
  - Unit: renderização da lista, formulário
  - Integration: CRUD completo com mock de API
- **NFR:** lista carrega em ≤ 1s

## Done means
- CRUD funciona no app
- Dados persistem offline
- Testes passam

## Scope extension — catálogo e estoque de produtos (2026-08-01)

- [x] Tabela separa materiais de produtos por unidade.
- [x] Catálogo inicia vazio, sem produtos pré-cadastrados.
- [x] Produto definido pelo usuário possui nome, descrição, valor e quantidade em estoque.
- [x] Produtos possuem cadastro, edição, exclusão, busca e persistência local.
- [x] Orçamento seleciona produtos, respeita o saldo e calcula subtotal.
- [x] Entrega do pedido abate o estoque uma única vez, com proteção idempotente.
- [x] Produtos são copiados como snapshot para orçamento, pedido e PDF.
- [ ] Sincronização via API; o schema PostgreSQL atual ainda não possui catálogo nem movimentos de estoque.
