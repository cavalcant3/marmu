# Story: Salvar Orçamento no SQLite Local (Offline-First)

## Context
Toda criação/edição de orçamento deve funcionar offline. Dados salvos localmente primeiro.

## Sources of truth
- `architecture.md` (Process Patterns — Sync Offline→Online)
- `prd.md` (Offline-first)

## Acceptance criteria
- [ ] Orçamento salvo em SQLite com status 'pending_sync'
- [ ] Dados: id (UUID local), cliente, medidas, material_id, preços, observações, created_at
- [ ] Lista de orçamentos lê do SQLite local (não depende de API)
- [ ] Edição de rascunho atualiza SQLite
- [ ] Schema versionado (migrations SQLite)

## Restrictions
- **Out of scope:** conflitos de merge complexos (versão simples: last-write-wins)
- **Protected:** nenhum

## Notes for Shuri (Dev)
- `react-native-sqlite-storage` ou `expo-sqlite`
- Schema: `orcamentos` table com todos os campos
- Index em `created_at` para ordenação

## Validation contract
- **Testes:**
  - Unit: CRUD no SQLite
  - Integration: salvar orçamento offline → ler de volta
- **NFR:** salvar ≤ 100ms

## Done means
- Orçamento salvo e recuperado offline
- Schema documentado
- Testes passam
