# Story: CRUD de Materiais no Backend

## Context
API para gerenciar a tabela de preços da marmoaria. Base para o cálculo automático de orçamentos.

## Sources of truth
- `architecture.md` (Data Architecture)
- `prd.md` (E02 — Tabela de preços)

## Acceptance criteria
- [ ] `GET /materiais` — lista todos os materiais do usuário logado
- [ ] `GET /materiais/:id` — detalhes de um material
- [ ] `POST /materiais` — cria novo material (nome, tipo, preco_por_m2, observacoes)
- [ ] `PUT /materiais/:id` — atualiza material
- [ ] `DELETE /materiais/:id` — remove material
- [ ] Validação: nome obrigatório, preco_por_m2 > 0
- [ ] Resposta paginada (limit/offset)
- [ ] Ordenação alfabética por nome

## Restrictions
- **Out of scope:** upload de fotos de materiais, variações de preço por região
- **Protected:** nenhum
- **Compatibility:** PostgreSQL
- **Security:** usuário só vê/edita seus próprios materiais (WHERE usuario_id = req.user.id)

## Notes for Shuri (Dev)
- Repository pattern: `materialRepository.ts`
- Zod schema para validação
- Index em `usuario_id` para performance

## Validation contract
- **Testes:**
  - Unit: validação de preco_por_m2 ≤ 0
  - Integration: CRUD completo com usuário autenticado
- **NFR:** listagem ≤ 200ms

## Done means
- API testada via Postman/curl
- Testes passam
