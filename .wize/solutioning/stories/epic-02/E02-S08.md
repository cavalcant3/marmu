# Story: Sincronização de Orçamentos com Backend

## Context
Quando app fica online, envia orçamentos pendentes para o backend e recebe atualizações.

## Sources of truth
- `architecture.md` (Process Patterns — Sync Offline→Online)

## Acceptance criteria
- [ ] Detecta conexão (NetInfo)
- [ ] Busca orçamentos com status 'pending_sync'
- [ ] Envia para `POST /orcamentos` em batch
- [ ] Atualiza status local para 'synced' após sucesso
- [ ] Se erro: mantém 'pending_sync', retry na próxima conexão
- [ ] Pull: recebe orçamentos do backend que não existem localmente
- [ ] Toast: "Sincronizando..." / "Sincronizado!"

## Restrictions
- **Out of scope:** resolução de conflitos complexos (LWW — last-write-wins)
- **Protected:** nenhum

## Notes for Shuri (Dev)
- Sync service: `syncService.ts`
- Retry com backoff exponencial
- Evitar sync simultâneo (flag `isSyncing`)

## Validation contract
- **Testes:**
  - Unit: detecta conexão, filtra pendentes
  - Integration: sync completo com mock de API
- **NFR:** sync de 10 orçamentos ≤ 3s

## Done means
- Orçamentos offline sincronizados com backend
- Retry funciona
- Testes passam
